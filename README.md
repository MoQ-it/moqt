# moqt

A Go (and, soon, TypeScript) implementation of IETF Media over QUIC Transport, [draft-ietf-moq-transport-22](https://datatracker.ietf.org/doc/draft-ietf-moq-transport/22/) (ALPN `moqt-22`). It is a reusable library with no knowledge of any application built on it. [moqit](../moqit) uses it for conferencing.

## Status

| `transport/rawquic`, `transport/wt` | Done. webtransport-go v0.13 has no stream priorities, so `SetPriority` is a no-op over WebTransport until a pass-through is upstreamed. |
| `relay` | Done: one upstream subscription per track with fan-out, served through a per-subgroup cache (each subscriber has its own cursor, so slow subscribers don't block others).<br>• Joiners are served from cached Groups via LOCATION_FILTER, e.g. relative start 1 = the current group<br>• NEW_GROUP_REQUEST forwarding per §9.20.19<br>• the upstream subscription is dropped after a linger period<br>• PUBLISH_DONE is passed on to subscribers<br>• PUBLISH_NAMESPACE / SUBSCRIBE_NAMESPACE routing<br>• hooks: `Authorizer`, `UpstreamResolver` (other relay nodes), `ObjectHook` (e.g. audio levels)<br>• **Delivery timeouts:** a subgroup still being sent `DeliveryTimeout` (default 1 s, or the subscriber's `SUBGROUP_DELIVERY_TIMEOUT`) after a newer Group started is reset, so congested subscribers skip to the live edge<br>• FORWARD=0 resets subgroups in progress<br>Not yet: datagram caching, the EndObject of absolute ranges. |

| `cmd/moqt-pubsub` | Synthetic clock-track publisher/subscriber that reports per-object latency (`moqt://` for raw QUIC, `https://` for WebTransport). |

Everything specific to a draft lives in `wire/v22`. A later draft or the RFC goes in a sibling package.

## Try it

```sh
go run ./cmd/moqt-relay -v &
go run ./cmd/moqt-pubsub pub -url moqt://localhost:4443/moq -ns moqit/r1/p/alice -track clock &
go run ./cmd/moqt-pubsub sub -url https://localhost:4443/moq -ns moqit/r1/p/alice -track clock
```

## Testing

```sh
go test ./...
(cd ts && npm install && npx vitest run && npx tsc -p . --noEmit)
go test -tags browser ./ts/e2e        # needs google-chrome and/or firefox
go test -run '^$' -fuzz FuzzDataStreams -fuzztime 1m ./wire/v22   # also FuzzReadMessage, FuzzParseDatagram
```

`testdata/v22/*.json` holds the golden vectors. They are hand-encoded from the spec (including the spec's own examples), not generated by this encoder, and both the Go and TS implementations test against them.

## Draft-22 ambiguities and how they are resolved here

These are the places to check first when interop with another implementation fails.

1. **FILL_TIMEOUT (0x0A) and RENDEZVOUS_TIMEOUT (0x04) encoding.** The draft does not state it. This implementation uses a varint, like every other millisecond parameter.
2. **FILL_PARAMETERS (0x23) contents.** The draft says "a sequence of Parameters … encoded as if they were Parameters for a separate message" inside a length-prefixed value. This implementation writes them without a leading count, since the length prefix already bounds them.
3. **Fetch End of Range markers (0x8C / 0x10C / 0x20C).** Group and Object are encoded as **absolute** IDs. Read as deltas, a marker could not end inside the current group. This matches floatdrop/moq-go.
4. **NAMESPACE_DONE.** The draft both calls the field a suffix and says it "begins with the Track Namespace Prefix". It is treated as a suffix, the same as NAMESPACE.
5. **Fetch Object ID deltas within a group.** Read literally: a present delta gives `prior + delta` with no implicit +1, unlike subgroup streams; an absent delta gives `prior + 1`. This matches floatdrop/moq-go.

## Transport notes

- **Never FIN an empty server-opened stream.** Firefox 157 resets the whole WebTransport session when a server-opened unidirectional stream is closed with no payload. Resets are fine, so a subgroup with nothing to send must be reset. See `moqit/spikes/phase0`.
- **Empty subgroups never open a stream.** `TrackWriter.OpenSubgroup` opens its stream on the first `WriteObject`.
- **PUBLISH_DONE can overtake data streams.** A `Subscription` stays open until it has received the advertised Stream Count, or 2 s have passed.
- **Chrome connects to `localhost` over `::1`.** Relays must listen dual-stack (`:port`), or browsers must be given `127.0.0.1`.
- **Receive limits.** The receiver bounds peer-chosen lengths with `MaxObjectPayload` (16 MiB) and `MaxObjectProperties` (256 KiB). The fuzzer found the unbounded case.
